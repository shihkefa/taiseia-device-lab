## 已修正

1. S21 `02 41 41 03`：四位元組封包的命令只有一個 byte。舊版誤把 SUM 41 納入命令、顯示 AA；現在顯示 A，SUM 位置為 2。
2. CN105 未知 TYPE 63、空 payload、校驗正確：舊版未標示待確認；現在保留未知類型警示，可用「只看待確認」找到。
3. CN105 已知類型 payload 長度異常但 checksum 正確：現在獨立警示預期／實際長度，避免將校驗通過等同有效命令；空欄位不再產生零長度資料列。非零 CONNECT ACK／SET ACK 的未確認回覆值亦保留警示。
4. TaiSEIA 範例過去固定空調，現在依「設備（共通回覆使用）」載入該設備的 7 筆合成封包：SA Type 查詢／回覆、功能讀取／回覆、寫入／echo、完整狀態。未選型時預設空調；範例不冒充實機紀錄。

## 驗證結果

- `node --test tests/*.test.mjs`：180 項通過；新增 26 項轉譯覆蓋與回歸測試。
- Edge 實際介面：六種 TaiSEIA 範例各 7 筆、S21 8 筆、CN105 10 筆，均無校驗失敗。確認功能名稱、方向及代表數值。
- 搜尋／篩選／分頁：29 筆混合資料分成 20＋9；正確列出 1 筆校驗失敗、4 筆待確認；未知 CN105 類型搜尋得到 1 筆。
- TXT／JSON／剪貼簿：即使篩選只顯示 1 筆，完整報告仍保留 29 筆與欄位內容；JSON schema 為 `packet-translation-v1`。
- 擷取 JSON 貼入網頁：既有 CN105 現場紀錄 182 筆完整 frame 全部解碼，校驗失敗 0，頁面維持未連線，無主控台錯誤。
- 讀檔處理器：程式測試涵蓋六設備設定快照匯入、超過 1MB 拒絕、損壞 JSON、失敗後清除舊結果。瀏覽器檔案選取受到擴充功能未開放本機檔案存取限制，未把這條 UI 路徑列為瀏覽器實測通過；改以同一轉譯入口貼入 JSON 驗證。未更改使用者的擴充功能權限。
- 私有歷史擷取離線回放：S21 共 986 筆（511 筆有 checksum，其餘 ACK/NAK）；CN105 182 筆有 checksum，皆無校驗錯誤。原始接收區塊及事件依規則略過，避免與完整 frame 重複計數。原始現場紀錄不隨公開儲存庫發布。

## 判讀限制

校驗通過只代表框架校驗一致。S21 D2／D4、部分原始相容回覆、CN105 現場 GET 參數 01／SET FF 高位旗標，仍有尚未確認的語意；警示屬預期結果。單一 ACK 不足以推定完整握手。未知功能、列舉、機型擴充保持原始值，不套用其他設備的定義。

本次確認的是目前模擬功能表及已實作協議子集的轉譯一致性，並回放先前紀錄；沒有重新操作每一種實體家電，也不是官方規格認證。洗衣機、空氣清淨機等來源未完整開放的功能仍依研究表標示可信度。
