# Daikin X50A 設備端模擬

v1.3.9 依公開控制器的請求及回覆解碼，反向實作瀏覽器設備端。這是可設定的通訊子集，尚未以使用者的實體 X50A 控制器驗證。SIM-X50A 是模擬宣告型號，並非從控制器辨識出的室內機。

## 固定來源

- [RevK/Faikout 控制器](https://codeberg.org/RevK/ESP32-Faikout/src/commit/fd0db3a721d4cb9e56450442a4a6f2c8dd79e658/ESP/main/Faikout.c)：`daikin_x50a_command`、`daikin_x50a_response`、AA/BA/BB 啟動順序、CA/CB 控制及 UART 設定。固定 commit `fd0db3a721d4cb9e56450442a4a6f2c8dd79e658`。
- [RevK 設備端測試模擬器](https://codeberg.org/RevK/ESP32-Faikout/src/commit/202b9efeb52859fdee98a02fad6c08c20402c1cf/Tools/Simulators/faikin-x50.c)：回覆角色、BA/BB 參考樣本及 B7 特殊回覆。該模擬器的 CA 風速欄位和 UART 停止位元未直接照用；以控制器實際解碼位置及設定為準。
- [Daikin2MQTT 控制器](https://github.com/maxmacstn/Daikin2MQTT/blob/acfe195e33db3cb5d4529af0ccc6938a0742a8dd/src/DaikinController/DaikinController.cpp) 與 [UART](https://github.com/maxmacstn/Daikin2MQTT/blob/acfe195e33db3cb5d4529af0ccc6938a0742a8dd/src/DaikinController/DaikinUART.h)：上下風向 CB 旗標／BE 讀回，以及 B7 室外溫度／頻率映射。固定 commit `acfe195e33db3cb5d4529af0ccc6938a0742a8dd`。

上述為研究實作，沒有官方完整規格。機型擴充與未公開位元不能據此推定。

## UART 與框架

預設 **9600 / 8E1**，符合兩份控制器程式。舊公開設備模擬器採 8E2，故自動掃描也包含 9600 / 8E2；若已在該組收到有效 X50A 請求，保留其停止位元。可改手動串口參數。控制器若只在上電送一次探測，請先選 X50A 再重啟控制器。

```
06 CMD LEN 01 ROLE [PAYLOAD…] CHECKSUM
```

`LEN` 在 byte 2，包含整個封包；控制器請求 `ROLE=00`、一般設備回覆 `06`、部分特殊回覆 `12`。Checksum 為前面所有 bytes 加總的反碼，使整包加總 `& FF = FF`。

與 TaiSEIA 同為 06 起始，但長度、角色與校驗不同；不把單一 06 視為 X50A 握手。自動辨識僅由已支援、長度正確、角色為 00 的完整有效請求鎖定。模擬設備成功送出 AA 就緒回覆後，仍需收到並成功回覆後續控制器命令，才列為握手流程完成。

## 支援命令

| CMD | 請求 payload | 模擬回覆 |
|---|---|---|
| AA | 單一 01 | 1 byte 就緒旗標 |
| BA | 空 | 29 bytes：可設定模擬型號及原始參考尾端資料 |
| BB | 空 | 20 bytes 固定相容樣本，完整能力語意未確認 |
| CA | 17 bytes | 17 bytes 設定狀態：電源、模式、溫度、風速、冷暖狀態、從屬／故障原始欄位 |
| CB | 2 bytes | 2 bytes 冷暖狀態／風速 |
| BD | 空 | 29 bytes：進風、室溫參考欄位、盤管、設定溫度 |
| BE | 空 | 9 bytes：RPM、風向、擺風及防凍旗標 |
| B7 | 空 | 32 bytes：室外溫度／壓縮機頻率；或可選 ROLE 12 的未支援樣本 |

CA 的全零 payload 為查詢。已知更新欄位為 byte 0 的 `2+power`、byte 1 的 `10|mode`、byte 3 整數溫度及 byte 4 的 `80|十分位`。模式 0/1/2/3/7 分別為送風／暖房／冷房／自動／除濕。溫度範圍 10–32°C、步進 0.1°C 是本模擬設定，不是全機型能力保證。

CB 的第二 byte：bit 7 為風速更新旗標、bits 4–6 為風速 0–5（0 自動）；bit 3 為風向更新旗標、bits 0–2 為位置 0–4 或 7 擺動。沒有更新旗標的欄位保持原狀。未確認每個數字的實際葉片角度，介面不標示猜測的角度名稱。

CA 狀態的風速在 payload **byte 6 的高位**，與公開控制器讀取位置一致；不使用舊模擬器中的 byte 5 風速寫法。BE 風向在 byte 4、RPM 為 byte 2–3 小端序。BD／B7 溫度採 `int16 little-endian / 128`，0.1°C 設定轉成 Q7 時可能有小於 1/256°C 的量化差異；零溫度有些控制器視為未提供，轉譯會提示。B7 頻率依 Daikin2MQTT 的 payload 26–27 小端序／10 映射，保留機型差異警示。

未支援的命令、寫入延伸欄位、無效列舉或數值，整包拒絕且不修改任何狀態，也不回假成功。錯誤校驗、設備回覆 echo 及未完成框架不執行。B7 特殊回覆不視為正常狀態。BB 與 BA 尾端僅為明示參考樣本，不宣稱真實功能能力。

## 操作與驗證

設備選「Daikin 空調（X50A）」；可先執行離線測試，得到 9 RX／9 TX／0 異常並明示離線握手。封包轉譯新增「X50A 初始化／控制」16 包合成範例，也支援 HEX、混合連續封包、擷取 JSON、欄位位置、角色／方向與校驗提示。

v1.3.9 共 217 項測試通過，新增 X50A 框架、固定向量、原子寫入、所有已支援模式、Q7 負溫、風速／風向旗標、分段黏包、雜訊恢復、掃描 UART、校正期間殘包保留、實際 app 事件／模擬 Serial Streams、握手證據及被動轉譯測試。瀏覽器確認離線控制後讀回、16 包轉譯、B7 特殊回覆與設定套用，無主控台錯誤。這些不等於實體串口時序或控制器相容性實測。

本版未加入 X50A 蜂鳴器欄位：所核對的公開協議沒有足夠對應，依使用者要求不顯示其蜂鳴器狀態。P1P2 仍為暫停中的獨立草稿，未納入本版。
