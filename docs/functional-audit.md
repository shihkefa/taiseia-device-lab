# v1.3.1 功能檢查紀錄

日期：2026-11-02（Asia/Shanghai）。檢查對象：六類 TaiSEIA、Daikin S21 v2、三菱電機 CN105 標準空調子集。環境：Windows、Node.js 24.22.1、桌面 Edge。

## 結論

修正後完整測試 **143 通過、0 失敗**。另執行 **1,400 次**欄位邊界讀寫與雜訊恢復檢查，沒有未解決失敗。這些數字包含重疊的案例，並非特定機型實體相容性認證。

程式、模擬 Web Serial 與實際瀏覽器操作均有檢查；實體 COM 控制器與電氣／時序未測，不能據此保證所有硬體都能握手。

## 修正內容

1. 自動辨識遇到前導 `02` 雜訊時，S21 解析可能把後面的 CN105 封包長度 `02` 當作新起點，導致有效 CONNECT 被吞掉。現在先辨識後續完整有效命令，再重新同步。
2. 額外 `06` 加上 TaiSEIA 註冊查詢，可能剛好形成另一個 XOR 正確的非請求框架。現在會重新對齊真正的控制器請求。三協議均用全部 256 種單一前導位元組測試。
3. CN105 狀態中未定義的電源／模式／溫度等數值，原先只在欄位文字顯示未知，整包卻仍標示正常。現在明確列為待確認；checksum 通過與內容語意有效分別呈現。
4. TaiSEIA 設定匯入現在拒絕未支援的 `protocol`。功能額外 metadata 不得切換其他協議的數值解析，功能標籤也不會直接插入任意 HTML。
5. 清除擷取時同步清除舊設定快照，避免反覆切換設定與清除紀錄後仍累積快照。檢視舊 TaiSEIA 紀錄時使用該協議的數值格式。

## 自動測試範圍

- 六類 TaiSEIA 的所有功能：合法邊界與列舉值寫入／讀回，唯讀與停用功能拒絕，FFFF、負數及縮放。
- S21 各狀態命令、獨立編碼、特殊 checksum、ACK/NAK、未指定溫度、原始回覆表與設定隔離。
- CN105 旗標寫入、傳統／半度溫度、感測、故障、功率、遠端室溫、特殊模式、不合法命令原子性。
- 三協議拆包／黏包、雜訊、校驗失敗、逾時、回覆不得當作請求、協議鎖定。
- 模擬 Web Serial：同埠切參數、4 秒輪巡、60 秒停止、取消／中斷／重連、延遲排程取消、錯誤狀態恢復。
- 模擬 app：CN105 8E2→8E1 校正後才回覆、CONNECT 後續命令證據、轉譯不影響串口或設備狀態。
- 設定驗證、匯入 metadata、擷取上限／重複封包／CSV 引號、被動轉譯、方向歧義及匯入限制。

## 尚未驗證或未支援

實際控制器型號、USB-UART 電位與延遲、開機單次握手、長時間實機連線、機型私有能力與特殊指令仍需實體收發紀錄。洗衣機／清淨機的部分功能屬公開部分程式建立的研究設定。

S21 v3、P1P2、X50A，以及 CN105 安裝模式、硬體功能表、特殊機型溫度表、定時器等仍依各協議文件所列範圍。參考 [S21](s21.md) 與 [CN105](cn105.md)。
